BAB 1: Company Profile & Business Process

End-to-End Business Process

  • 1. Kontrak & Pemesanan: Klien B2B (Mayora, Gokana) negosiasi langsung/email. Pelanggan B2C via e-commerce (Tokopedia, Shopee).
  • 2. Pengadaan (Inbound): Mencari supplier, menerima pasokan, sortir kualitas, lalu disimpan di gudang.
  • 3. Operasional Produksi: Persiapan (cuci, kukus, giling), pemasakan sesuai resep rahasia, dan pengisian botol (packaging).
  • 4. Testing / QC: Pengujian sampel berkala untuk konsistensi (uji mikrobiologi, viskositas, brix, salt, pH).
  • 5. Logistik Keluar (Outbound): Proses pesanan distributor, packing, pengiriman via armada internal/ekspedisi.
  • 6. Layanan (Service): Penanganan keluhan, umpan balik pelanggan, dan pembuatan invoice otomatis via software Accurate.

BAB 2: Problem Statements & Database Planning

Problem Statements

Inventory Record Inaccuracy & Ghost Stock

  • Jeda Data: Stok yang dipesan di e-commerce (Tokopedia/Shopee) belum terpotong otomatis di "Accurate".
  • Ghost Stock: Sistem menampilkan stok tersedia, padahal fisik sudah habis/di-booking.
  • Dampak: Pembatalan pesanan dan hilangnya kepercayaan konsumen.

Human Error & Kertas Manual

  • Pencatatan Ganda: Stok gudang, Quality Control, dan resep produksi masih menggunakan kertas.
  • Batch Tracking: Sangat rentan kesalahan karena staff harus menyalin data batch manual dari botol ke form.
  • Dampak: Kesulitan validasi kualitas jika terjadi retur.
BAB 2: Problem Statements & Database Planning

Data Isolation & Mission Objectives

Data Isolation & Manajemen Reaktif

  • Tidak ada real-time dashboard untuk manajemen (Silo data antar Excel).
  • Persetujuan kredit B2B berjalan lambat.
  • Ketergantungan data produksi pihak ketiga yang menghambat visibilitas operasi.

Mission Statement & Objectives

"Merancang database terintegrasi dari pengadaan bahan baku hingga distribusi untuk akurasi real-time."

  • Target 1: Otomatisasi pelacakan batch (FEFO).
  • Target 2: Sinkronisasi pemotongan stok dengan platform e-commerce.
  • Target 3: Menghasilkan laporan daily ghost stock untuk mitigasi dini.
BAB 2: Problem Statements & Database Planning

Metode Pengumpulan Data & Format Standar

Teknik Pengumpulan Fakta

Mengumpulkan data dari dokumen kertas (Surat Jalan, QC), aplikasi "Accurate", dan observasi lapangan melalui tiga tahap:

  • Examining Documentation: Menganalisa format laporan, invoice, dan kartu stok.
  • Interviewing: Tanya jawab dengan user di berbagai divisi (Gudang, Produksi, dll).
  • Observing: Mengamati langsung proses operasional di pabrik KS FOOD.

Standar Format Database

Untuk menjaga konsistensi, ERP ini dirancang dengan aturan baku:

  • Naming Convention: Menggunakan format ERDish (camelCase) untuk atribut (misal: kodeBarang, tanggalMasuk).
  • Date/Time FEFO: Format tanggal & waktu ketat untuk mengelola masa kadaluwarsa (First Expired, First Out).
  • Tipe Data Numerik: Penggunaan Decimal/Integer akurat untuk konversi satuan resep rahasia (gram, ml).

BAB 3: System Definition & Requirement

System Objectives & Boundaries

Tujuan Sistem (Objectives)

  • Proprietary E-Commerce & Omnichannel: Platform mandiri tersinkronisasi dengan marketplace eksternal.
  • Single Source of Truth (SSOT): Satu database terpusat untuk rekaman pergerakan persediaan.
  • Mencegah Ghost Stock: Stok fisik terkunci (reserved) secara otomatis saat ada pesanan masuk.
  • Otomatisasi Invoicing: Penerbitan Surat Jalan dan Invoice otomatis dari data transaksi.

Cakupan Sistem (Boundaries)

Sistem mencakup manajemen dari hulu ke hilir:

  • E-Commerce Mandiri & Omnichannel: B2B, B2C, integrasi API eksternal.
  • Gudang (Warehouse Management): Perekaman stok berbasis Batch dan Expired Date (FEFO).
  • Produksi: Pencatatan Job Order dan pemotongan alokasi bahan baku otomatis berdasarkan resep.

Users View and Roles

BAB 3: System Definition & Requirement

Aliran Data & CRUD Analysis

Aliran Data Bisnis

  • Pengadaan: Deteksi stok menipis -> Generate UID batch & expire date saat barang tiba.
  • Produksi: Job Order mengambil bahan baku -> Potong stok (FEFO) -> Hasil lolos QC mendapat QR Code barang jadi baru.
  • Penjualan (Omnichannel): Menarik data pesanan B2B/B2C beserta rincian biaya -> Kunci (reserve) stok tersedia.

CRUD Analysis

  • [C]reate: Merekam pesanan pelanggan, menambah rekam batch bahan baku baru.
  • [R]etrieve: Dashboard ketersediaan stok (Available to Promise), rekap performa penjualan.
  • [U]pdate: Memperbarui fisik stok (mutasi in/out), mengubah status pesanan (Pending -> Delivered).
  • [D]elete: Membatalkan pesanan (Void/Soft Delete), menghapus draf PO salah input.

BAB 4: Conceptual ER Modeling

Konsep Relasi Antar Entitas

Memastikan integritas data lintas modul dengan notasi Crow's Foot.

Super-type ke Sub-type (1:1)

Entitas profil MS_Customer diturunkan spesifik menjadi MS_Corporate (B2B) atau MS_Retail (B2C) untuk mengelola atribut yang berbeda secara rapi.

Pemecahan Many-to-Many

Satu pesanan dapat menggunakan banyak promo, dan sebaliknya. Relasi ini dijembatani entitas pivot TR_Order_Promo (1:M).

Integrasi Lintas Modul (1:M)

TR_Production_Result diikat ke TR_Product_Batch. Setiap "panen" hasil masak yang lolos QC otomatis menciptakan satu batch barang jadi baru di Gudang.

BAB 7: Physical Database Design

Implementasi DDL & DML

Translasi Logical Schema menjadi tabel fisik di DBMS MariaDB beserta pengujian manipulasinya.

Data Definition Language (DDL)

Pembuatan tabel dengan mendefinisikan tipe data, batas maksimal, dan Constraints (Primary & Foreign Key).

CREATE TABLE `ms_customer` (
  `customerId` varchar(20) NOT NULL,
  `userId` varchar(20) NOT NULL,
  `fullName` varchar(100) NOT NULL,
  `type` enum('CORPORATE','RETAIL') NOT NULL,
  `isActive` tinyint(1) NOT NULL DEFAULT 1,
  `createdAt` datetime NOT NULL DEFAULT current_timestamp(),
  PRIMARY KEY (`customerId`),
  CONSTRAINT `fk_cust_user` FOREIGN KEY (`userId`) 
    REFERENCES `ms_user` (`userId`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Data Manipulation Language (DML)

Pengujian operasi query dasar seperti `INSERT`, `UPDATE`, `DELETE`, dan SELECT JOIN antar modul.

-- Contoh Insert Data Master
INSERT INTO `ms_category` (`categoryId`, `name`) 
VALUES ('CAT-01', 'Bahan Baku Mentah');

-- Contoh Query Multi-Join (Pelacakan PO)
SELECT p.procurementId, s.companyName, p.totalAmount 
FROM tr_procurement p
JOIN ms_supplier s ON p.supplierId = s.supplierId
WHERE p.status = 'COMPLETED'
ORDER BY p.createdAt DESC;
BAB 7: Physical Database Design

Keamanan & Kontrol Transaksi (DCL & TCL)

Penerapan keamanan Role-Based Access dan perlindungan integritas data melalui mekanisme transaksi.

Data Control Language (DCL)

Membatasi akses pengguna (Grant & Revoke) ke objek basis data berdasarkan wewenangnya (misal: Admin Gudang). 

-- Membuat User Gudang
CREATE USER 'wms_admin'@'localhost' 
IDENTIFIED BY 'wms#123';

-- Hak Akses Khusus Modul Gudang
GRANT SELECT, INSERT, UPDATE 
ON ksfood.tr_product_batch 
TO 'wms_admin'@'localhost';

Transaction Control Language (TCL)

Menjamin rentetan operasi rentan (seperti pemotongan stok berantai) dieksekusi secara Atomik.

START TRANSACTION;
-- Mengurangi stok batch
UPDATE tr_product_batch 
SET currentStock = currentStock - 10 
WHERE productBatchId = 'BAT-99';

-- Mencatat histori pergerakan
INSERT INTO tr_stock_movement (...) VALUES (...);

COMMIT; -- Simpan jika semua sukses
-- ROLLBACK; -- Batalkan jika terjadi error
